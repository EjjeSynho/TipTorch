# ETC comparison

The goal of this execution plan is to write a routine that compares the distributions of PSF parameters between real on-sky PSFs and simulated ones. For the simulated PSFs, the routine must compare MUSE-NFM PSFs simulated with vanilla TIPTOP against PSFs simulated with calibrated TipTorch.

## Resources
* The PSF parameters in question are computed in `development/get_fwhm_tiptop_multi_optimized.py`. The results of running this script are already stored in `./data/Enrico_ETC/onsky_PSFs_params/All_PSF_***.nm`. The PSF names listed in these FITS files should exactly match the PSFs in the dataset used for the NFM predictor calibration, but verify this.

* The routine in `development/run_tiptop_random_carlo.py` generates random samples based on parameter distributions intrinsic to the turbulence categories (TCs). The files and configs inside `./data/Enrico_ETC/pregenerated_random_PSFs/***nm/` contain a few pre-generated PSFs.

* The folders `./data/calibrations/VLT_CALIBRATION/VLT_PUPIL` and `./data/Enrico_ETC/` contain the data referenced by the path definitions in Enrico's scripts.

## Execution plan

### TIPTOP side
1. Clone the astro-tiptop repository (https://github.com/astro-tiptop) with all necessary dependencies into the projects folder (one level above the TipTorch repo folder).
2. Translate all of Enrico's comments from Italian into English in all routines.
3. Change the path definitions inside Enrico's scripts to the ones relevant for the current system.
4. Make Enrico's routines work on this machine.
5. Numerically test the updated `development/run_tiptop_random_carlo.py` against the pre-generated PSFs in `./data/Enrico_ETC/pregenerated_random_PSFs/***nm/`.
6. Run it and store the results in `./data/Enrico_ETC/generated_random_PSFs/***nm/`.

### TipTorch side
1. Create a Monte-Carlo PSF generation routine for TipTorch. It must reproduce `run_tiptop_random_carlo.py` as closely as possible, but use TipTorch with the calibration. For inspiration, see the relevant ETC section in `machine_learning/validate_NFM_calibrator.py`.
2. Run the routine and store the results in `./data/Enrico_ETC/tiptorch_random_PSFs/***nm/`.
3. Create a routine similar to `get_fwhm_tiptop_multi_optimized.py` that computes exactly the same metrics for the TipTorch PSFs.
4. Finally, combine the results from TIPTOP and TipTorch, then create and run routines that compare the distributions of the PSF parameters as a function of TC.

Feel free to change the order of these steps if necessary.

## Requirements
* Make sure that TipTorch and TIPTOP use the same wavelengths.
* **DO NOT** install astro-tiptop into this conda environment. For now, import it in Enrico's routines by adding it to the path.
* The number of TipTorch and TIPTOP PSFs must be approximately equal to the number of on-sky samples.
* (optionally) select only the PSFs from the validation dataset to do compute the stats.

## Outputs
The routine should output a diagram showing the distributions of the PSF parameters for every TC. It must demonstrate how well the distributions generated by calibrated TipTorch and by vanilla TIPTOP match the real on-sky distributions. The goal of this test is to find out if calibration help to represent the real PSF params distribution more accurately.

## Surprises & Discoveries

- Observation: TIPTOP HEAD (v1.6.0, 2026-10-07) does not reproduce the pregenerated PSFs although the HO/LO residuals match.
  Evidence: RESH 108.848 vs 108.844 nm, RESL 16.347 vs 16.335 nm, but SR 0.55809 vs 0.45534 and FWHM 51.8 vs 56.8 mas.
  Consequence: Enrico's SPIE tuning (`extraerr`, `get_extra_jitter_*`) belongs to TIPTOP 1.4.3; the comparison uses that version.
- Observation: `import sklearn` fails in a bare shell (`GLIBCXX_3.4.31` missing for `pyarrow`) unless the `TipTorch` env is
  activated (`LD_LIBRARY_PATH=$CONDA_PREFIX/lib`) or `torch` is imported first. Consequence: run scripts from the activated env.
- Observation: `tiptop.asterismSimulation` imports `torchmetrics` (absent) only for its NN asterism selector.
  Consequence: `tiptop_env.py` registers a stub module instead of installing it.
- Observation: setuptools_scm `_version.py` files are not in the git clones. Consequence: created by hand (untracked) in each repo.
- Observation: TIPTOP 1.4.3 computes the header FWHM with `getFWHM(method='contour')` without the `rebin` argument that HEAD
  adds for undersampled PSFs. Evidence: `tiptop_metrics` with rebin differed by ~1 mas from the stored headers, without rebin it
  matches all 25 files. Consequence: `ETC_psf_metrics.tiptop_metrics` follows the 1.4.3 call.
- Observation: `maoppy.psffit` prints every iteration; `data['telemetry']` of the dataset cache is an object array of dicts.
  Consequence: stdout is redirected during the PSFAO fit; the telemetry DataFrame is built from `list(...)`.
- Observation: the PSFAO-fit pool with 16 workers and default BLAS threading ran at ~9 min per wavelength (329 % CPU per
  worker); 48 single-threaded workers measure a wavelength in < 1 min. Consequence: `ETC_compute_PSF_params.py` sets
  `OMP/MKL/OPENBLAS_NUM_THREADS=1` and defaults to 48 processes.
- Observation: both simulators respond to the sampled conditions as expected (Spearman rho at 700 nm, random sampling):
  TIPTOP FWHM-airmass 0.86, Strehl-seeing -0.70; TipTorch FWHM-airmass 0.49, FWHM-seeing 0.42, Strehl-seeing -0.64; the
  calibrator's predicted r0 follows r0(seeing) with rho 0.90 (median 0.131 m vs 0.157 m input at 500 nm). On sky the
  correlations are weaker (FWHM-airmass 0.30, Strehl-seeing -0.43), i.e. the on-sky scatter is dominated by factors neither
  simulator samples.

  Enrico's uniform sampling within each TC, NGS J magnitude uniform in 9-16 (the default of `generate_random_observations`, the

  Rationale: paired TIPTOP/TipTorch samples, sample size equal to the on-sky one per TC as required by the plan.
  Date/Author: 2026-10-11, Claude.
- Decision: a second, optional sampling mode `--sampling onsky` replays the on-sky (seeing, tau0, NGS mag, airmass) rows of each TC
  (`generated_random_PSFs_onsky/`, `tiptorch_random_PSFs_onsky/`, comparison tag `_replay`).
  Rationale: removes the mismatch between the uniform Monte Carlo conditions and the real ones (on-sky airmass is mostly < 1.3,
  seeing in TC100 reaches 2.1"), so that the remaining differences are due to the PSF models only.
  Date/Author: 2026-10-11, Claude.
- Decision: the TipTorch Monte Carlo follows the ETC recipe of `validate_NFM_calibrator.py`: each sample borrows config and
  telemetry from a random dataset observation (template, seed 0, ids stored in `telemetry.csv` / `predicted_params.fits`),
  overrides atmosphere (seeing, L0/GLF/ASM wind of the TC, 3-layer profile at 0/2/20 km), LGS flux, zenith angle and the
  IRLOS regime (frequency 500/200 Hz, gain 1/68/100, NGS magnitude) and imputes the AO diagnostics. The MASS-DIMM turbulence
  velocity is derived from the sampled tau0 (0.314 r0 / tau0) instead of the TC wind constant.
  Rationale: the calibrator predicts r0, L0, Cn2, wind, jitter and NCPAs from telemetry; the sampled tau0 would otherwise be unused.
  Date/Author: 2026-10-11, Claude.
- Decision: TipTorch PSFs are rendered on the calibrated 199 px grid and cropped to TIPTOP's 100 px field (peak at pixel 50);
  all parameters are computed on unit-sum 100 px PSFs for both simulators. The PSFAO Strehl uses the PSF wavelength (Enrico's
  script hard-coded 700 nm for every wavelength) and TIPTOP's header metrics are recomputed with the same P3 calls for TipTorch.
  Rationale: identical measurement code for both simulators is the point of the comparison.
  Date/Author: 2026-10-11, Claude.

## Outcomes & Retrospective

Implemented: the astro-tiptop stack runs from pinned checkouts via `development/tiptop_env.py`; Enrico's two routines are
translated, path-fixed and parametrised; `tests/test_ETC_tiptop_pregenerated.py` reproduces the 25 pregenerated PSFs to
machine precision; `run_tiptorch_random_carlo.py` replays the same observation table through the calibrated NFM model;
`ETC_psf_metrics.py` / `ETC_compute_PSF_params.py` measure both simulators with identical code; `ETC_compare_distributions.py`
produces the per-TC distribution diagrams and the distance summaries. Three comparison variants were run (all on-sky PSFs,
validation split only, replay of the on-sky conditions).

Scientific outcome: with the current calibrator bundle (`best_calibrator_bundle.pth`, 2026-10-11) the calibrated TipTorch
Monte Carlo does **not** represent the on-sky parameter distributions better than Enrico's tuned TIPTOP. TipTorch PSFs are
systematically too sharp and too uniform: FWHM 47-50 mas at 700 nm against 58-63 mas on sky with a 3x smaller spread, Strehl
(both definitions) about twice the on-sky median, EE50 too high by 0.05-0.1 at all TCs. Vanilla TIPTOP reproduces FWHM and
the PSFAO Strehl better (the TC- and wavelength-dependent `jitter_FWHM` / `extraErrorNm` tuning was fitted on these same
on-sky data, so it is not an untuned model), while its peak-ratio Strehl and EE50 are too low at 500-600 nm, where TipTorch is
closer. Both simulators react to seeing and airmass more strongly than the on-sky sample does (Spearman rho of FWHM with
airmass: TIPTOP 0.86, TipTorch 0.49, on-sky 0.30).

Caveats / limitations: (1) the on-sky `strehl_tt` and `ensquared_tt` columns were computed by Enrico with code not available
here; they are compared with TIPTOP-style metrics on the simulated 100 px PSFs. (2) The TipTorch Monte Carlo borrows the
nuisance telemetry (pointing, exposure, temperature) from random dataset observations and imputes the AO diagnostics; on sky
the LGS diagnostics carry part of the PSF variance, which explains part of the too-small TipTorch spread. (3) The calibrator was
trained on the whole history while TIPTOP's config models the post-2022 IRLOS (`--since` reproduces Enrico's date cut).
(4) 18/466 on-sky rows could not be matched to the dataset by observation time.

Follow-ups: inspect why the calibrated model under-predicts the FWHM for ETC-like telemetry (jitter `J_ctrl` vs IRLOS
features, imputed LGS diagnostics), possibly condition the Monte Carlo telemetry on the on-sky LGS statistics; re-run the
comparison after retraining (`run_tiptorch_random_carlo.py --overwrite`, then `ETC_compute_PSF_params.py --source tiptorch`
and `ETC_compare_distributions.py`).
